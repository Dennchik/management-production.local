## Задачи: AJAX-выходы, занятые рулоны, недобор, права, отмена

Миграции БД не нужны: `production_task_outputs.actual_weight` уже nullable, занятость рулонов считается по `production_task_inputs`.

### 1. Права задач
- `app/Models/Role.php`: в `ACTIONS` добавить `'cancel' => 'Отменять'`, `'execute' => 'Выполнять'` — появятся в UI «Роли и права» автоматически.
- `database/seeders/UserSeeder.php`: оператор `tasks => [view, execute]` (право edit убирается — больше не правит задачу), менеджер `tasks => [view, create, edit, cancel, execute]`; перезапустить сидер.
- `routes/web.php`: `start`, `addInput`, `saveInput`, новые outputs-роуты и `complete` → `can.do:tasks,execute`; новый `cancel` → `can.do:tasks,cancel`. create/store/edit/update остаются как есть.

### 2. Произведённые рулоны — автосохранение по AJAX (как расход)
- `start()`: при старте создаёт первую строку `ProductionTaskOutput` (номер `{number}/1`, вес пустой).
- Новые методы `ProductionTaskController` (право execute, только в работе): `storeOutput` (POST /tasks/{task}/outputs — добавить строку с номером `{number}/{N+1}`), `updateOutput` (PUT /tasks/{task}/outputs/{output} — сохраняет номер и вес, отвечает `{made, left}`), `destroyOutput` (DELETE — нельзя удалить последнюю строку).
- `complete()`: выходы берёт из БД вместо формы; требует хотя бы одну строку с весом.
- `views/tasks/show.blade.php`: секция «Произведённые рулоны» рендерится из БД в контейнере `[data-task-outputs-section]`, поля без `name` (`data-output-number`/`data-output-weight`), свой индикатор «Сохранено».
- `resources/js/modules/pages/task.js`: `initOutputRolls` переписать по образцу `initRollWeights` — автосохранение с дебаунсом 700 мс, «Ещё рулон»/«Убрать» через fetch с подменой секции (как `refreshInputsSection`).

### 3. Занятые рулоны — вниз списка, отключены, с номером задачи
- `rollsForMaterials()`: рулоны, взятые другими задачами в работе (join по `production_task_inputs` + статус `in_progress`), не исключаются, а помечаются номером задачи; свободные сверху, занятые внизу.
- Опция в селекте: атрибут `disabled` (кастомный селект нативно не даёт кликнуть) + мелкий текст «взята в задачу №N».
- `addInput()`: серверный запрет брать рулон, уже взятый другой задачей в работе.

### 4. Завершение с недобором (1400 из 3000)
- `complete()`: убрать отказ «не выполнена по объёму». Недобор разрешён только при `may('tasks','edit')` (менеджер/админ); оператору — 403 «Недобор может завершить только менеджер».
- `ProductionTask`: метод `isShort()` (выполнена и произведено меньше плана); `statusClass()` для такого случая отдаёт `red-soft`.
- `resources/scss/components/status-chip.scss`: класс `.status-chip--red-soft` — светло-красный (мягче, чем красный «Отменена»).
- Прогресс-текст «1400 из 3000, осталось 1600» светло-красный при недоборе — на страницах задачи и списка.

### 5. Отмена задачи
- `cancel()`: POST /tasks/{task}/cancel, только из статуса «Ожидает», ставит `cancelled`.
- Кнопка «Отменить задачу» на странице (pending + право cancel) с подтверждением.

### 6. Проверка
`php artisan db:seed --class=UserSeeder`, `npm run production` (меняется SCSS), проверка в браузере: автосохранение выходов на живой задаче, занятые рулоны внизу с номером задачи, завершение с недобором менеджером (светло-красный статус и текст), отказ оператора (403 на правку задачи и на недобор-завершение), отмена задачи в статусе «Ожидает».
