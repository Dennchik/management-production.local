# План: Заказы с позициями + производственные задачи + права доступа

## 1. Заказ = шапка + позиции
- Миграция: таблица `order_items` (order_id, material_id, quantity, unit, sort_order). Существующие заказы переносятся в позиции (1 позиция из material_id/quantity), старые колонки `material_id`, `quantity` из `orders` удаляются.
- Заказ: `client_name`, **`address`**, `comment` + список позиций (материал-продукция, количество).
- Форма/страница заказа: шапка (имя, адрес, комментарий) + таблица позиций с добавлением строк (как входы/выходы в тех.операциях).
- На странице заказа — кнопка **«Создать задачи»**: для каждой позиции создаётся производственная задача.

## 2. Производственные задачи (отдельно от заказов, привязаны к заказу)
- Таблица `production_tasks`: order_id (nullable FK — можно и без заказа), material_id (что производить), quantity, machine_id (станок), status (`pending`/`in_progress`/`done`/`cancelled`), started_at/completed_at, created_by (user), comment.
- Таблицы `production_task_inputs` (task, material, roll, planned/actual weight) и `production_task_outputs` (task, material, roll_number, planned/actual weight, созданный roll_id).
- Многоэтапность: задача может быть на любой материал-«продукцию» (в т.ч. полуфабрикат). Когда этап выполнен — его рулон попадает на склад и может использоваться следующей задачей. Из заказа создаётся по задаче на позицию; при необходимости оператор/менеджер добавляет задачу на промежуточный материал вручную.
- **Станок**: таблица `machines` (имя) + у пользователя свой станок.
- **Рабочее место оператора**: страница «Мои задачи» — задачи его станка. Открытие задачи → форма старта: указывает какой рулон взял по каждому входному материалу (селект рулонов выбранного материала) и номер выходного рулона. Завершение: фактические веса использованного/произведённого. По завершению — транзакция: списание с каждого входного рулона (MaterialIssue) и оприходование выходного рулона (MaterialRoll + MaterialReceipt), в комментарии — «Заказ №X / Задача №Y», user_id = текущий пользователь.

## 3. Пользователи, роли и права по объектам
- Простой **логин** (имя + пароль, сессия; пользователей идентифицирует name, email в системе нет): страницы входа/выхода, middleware.
- Таблицы: `roles`, `role_permissions` (role_id, object, action), у `users` — `role_id`, `machine_id`.
- Матрица объектов × действий: объекты = Материалы, Заказы, Производственные задачи, Склад (приход/расход), Рулоны, Ламинация, Технологические операции, Отчёты; действия = Смотреть, Создавать, Редактировать, Удалять.
- Страница управления ролями: матрица чекбоксов (сохраняется AJAX-ом).
- Страница пользователей: создание/редактирование, роль, станок.
- Проверка прав: через Laravel Gate (админ — всё); сайдбар скрывает пункты без права «Смотреть», контроллеры отдают 403.
- Вместо захардкоженного `user_id => 1` — текущий пользователь везде.

## 4. Порядок работ
1. Миграции + модели + логин/мидлвэр + сид (admin, роль «Администратор», оператор с станком).
2. Заказы: позиции + шапка с адресом, «Создать задачи».
3. Задачи: список по станкам, старт/завершение со списанием/оприходованием.
4. Роли: матрица прав, страница пользователей.
5. Проверка в браузере под админом и оператором.
