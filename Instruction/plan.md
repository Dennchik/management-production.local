1. Общая схема
	```
		МАТЕРИАЛЫ
		│
		▼
		ФИЗИЧЕСКИЕ РУЛОНЫ
		│
		│ используются как сырьё
		▼
		┌──────────────────────────────────────┐
		│       ТЕХНОЛОГИЧЕСКОЕ ЗАДАНИЕ        │
		│                                      │
		│   Маршрут:                          │
		│                                      │
		│   1. Ламинация                       │
		│   2. Кэширование                     │
		│   3. Печать                          │
		│   4. Резка                           │
		│                                      │
		└──────────────────────────────────────┘
		│
		▼
		ВЫПОЛНЕНИЕ КОНКРЕТНОЙ ОПЕРАЦИИ
		│
		├── входные материалы / рулоны
		│
		├── списание фактического сырья
		│
		├── производство нескольких рулонов
		│
		└── выходной ПФ
		│
		▼
		становится входом
		следующей операции
	```
2. Справочник материалов
   materials

	Это остаётся основной сущностью.
	```
	materials
	────────────────────────────────────
	id
	name
	code
	identifier
	grammage
	thickness
	format
	
	is_active
	
	created_at
	updated_at
	```
	Например:
	```
	Бумага ВП 60
	Фольга алюминиевая
	Пленка FPO
	Пленка БОПП
	Клей 1-компонентный
	Клей 2-компонентный
	```
	Здесь не нужно хранить жёстко:
	```
	lamination_allowed
	lamination_base_allowed
	printing_allowed
	cutting_allowed
	```
	В перспективной архитектуре это должно определяться маршрутом и типами входов операции.

	Текущие поля можно пока оставить для временной реализации.

3. Типы технологических операций
   production_operations
	```
	Справочник процессов производства.
	
	production_operations
	────────────────────────────────────
	id
	name
	code
	description
	
	is_active
	
	created_at
	updated_at
	```
	Например:
	```
	id	name	code
	1	Ламинация	lamination
	2	Кэширование	laminating
	3	Печать	printing
	4	Праймирование	priming
	5	Резка	cutting
	```
	Важно: Кэширование — отдельная технологическая операция, даже если в меню или интерфейсе оно находится рядом с ламинацией.

5. Операции внутри маршрута
   production_route_steps

	Это самая важная таблица.
	```
	production_route_steps
	────────────────────────────────────
	id
	
	production_route_id
	production_operation_id
	
	step_number
	
	name
	
	is_required
	
	created_at
	```

	Связь:
	```
	production_routes
	│
	│ hasMany
	▼
	production_route_steps
	│
	│ belongsTo
	▼
	production_operations
	```
	Пример.

	Маршрут «Стандартный»

	step_number	operation
	1	Ламинация
	2	Кэширование
	3	Печать
	4	Резка

	```
	Что может или должно использоваться во входе операции.
	
	production_operation_inputs
	────────────────────────────────────
	id
	
	production_operation_id
	
	name
	code
	
	input_type
	
	is_required
	
	min_quantity
	max_quantity
	
	sort_order
	
	created_at
	updated_at
	```

11. Очень важный момент — снятие рулона

	По ТЗ оператор может снять рулон из-за:
	
	* брака
	* невозможности использования
	* замены материала

	Я бы не смешивал это с обычным расходом.

	Нужна отдельная таблица событий рулона.
	```
	production_roll_events
	production_roll_events
	────────────────────────────────────
	id
	
	production_job_operation_id
	
	roll_id
	
	event_type
	
	weight
	
	reason
	
	user_id
	
	created_at
	updated_at
	
	Типы:
	
	connected
	disconnected
	waste
	completed
	
	Например:
	
	Рулон бумаги №101
	
	connected
	↓
	использовано 320 кг
	↓
	disconnected
	остаток 180 кг
	
	Или:
	
	Рулон фольги №205
	
	connected
	↓
	использовано 150 кг
	↓
	waste
	остаток 30 кг
	````
12. Полученные рулоны ПФ

	По ТЗ:

	После изготовления первого ролика оператор заносит вес полученного рулона ПФ.

	Значит результат операции нельзя хранить одним числом.

	Нужна отдельная таблица.
	```
	production_job_operation_outputs
	production_job_operation_outputs
	────────────────────────────────────
	id
	
	production_job_operation_id
	
	material_id
	
	roll_id
	
	roll_number
	
	weight
	
	created_at
	updated_at
	
	Каждый произведённый рулон:
	
	Отдельная физическая сущность
	
	Например:
	
	Операция Ламинация
	
	дала:
	
	ПФ рулон №PF-001 — 480 кг
	ПФ рулон №PF-002 — 475 кг
	ПФ рулон №PF-003 — 490 кг
	
	Каждый из них должен получить отдельный:
	
	material_rolls.id
	```
13. Как ПФ переходит на следующую операцию

	Это главный момент всей архитектуры.

	После ламинации:
	```
	material_rolls
	
	получает новый рулон.
	
	Например:
	
	material = МК3
	roll_number = PF-001
	weight = 480
	
	И этот же рулон затем выбирается во входе:
	
	Кэширование
	Полуфабрикат
	↓
	PF-001
	
	То есть физически:
	
	Ламинация
	│
	│ output
	▼
	material_rolls
	│
	│ input
	▼
	Кэширование
	```
